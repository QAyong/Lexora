# Spec-009：会话点击后的即时切换

**日期：** 2026-09-30
**状态：** 已实现（专项测试、类型检查和改动文件 lint 通过；完整预检被仓库 lint 问题阻断）

## 1. 背景

当前在桌面端点击侧边栏会话后，工作台会先等待目标会话完成初始化，再提交视图切换。初始化包含会话读取、草稿恢复、分支加载和消息时间线加载，因此用户在点击后仍看到旧会话，容易误以为点击没有生效。

相关实现：

- `apps/buddy/src/app/workbench/registerDesktopContributions.ts`：任务视图设置 `prepareBeforeOpen: false`，普通主区域替换不再等待目标视图准备完成。
- `apps/buddy/src/workbench/services/WorkbenchController.ts`：提交视图前仍执行当前视图的 `beforeClose` 保护。
- `apps/buddy/src/app/workbench/DesktopTaskContribution.vue`：已有 loading 和失败重试显示，可承接切换后的异步初始化。

## 2. 目标

点击侧边栏中的已有会话后（普通主区域替换路径，且当前视图的关闭保护已通过）：

1. 侧边栏选中态和主区域先切换到目标视图。
2. 目标会话初始化期间显示现有 loading 状态；初始化完成后显示目标会话内容。
3. 更早历史继续使用现有分页，用户滚动到顶部时再加载。
4. 加载失败时显示目标视图的失败状态和重试入口，而不是继续显示旧会话。

核心原则：

> 视图切换不等待目标会话初始化；会话数据在切换后异步恢复。

## 3. 需求边界

**包含：**

- 普通主区域中的任务视图替换先切换视图，再异步初始化。
- 复用现有 loading、失败和重试界面。
- 沿用现有最近时间线页和历史分页，不调整消息加载流程。
- 保留已有的关闭保护、请求取消和最后一次点击胜出逻辑。

任务视图同时支持已有会话（`task`）和新建草稿（`draft`），因此共用的打开时机设置也会影响普通主区域中新建草稿的切换反馈；草稿确认和自动保存行为不变。分屏打开不在本次改动范围内。

**不包含：**

- 不新增会话缓存、预取或新的状态管理系统。
- 不重构会话初始化、时间线分页或 Agent 运行状态和消息持久化。
- 不对历史消息引入网络流式传输；流式更新只继续用于正在运行的 Agent 输出。
- 不改变普通会话草稿的自动保存机制及新建草稿未发送内容的确认流程。
- 不处理运行中任务是否允许后台继续运行这一独立问题。
- 不改变工作区状态或文件面板行为；文件树和文件内容仍在用户打开面板或预览时按需读取。

## 4. 推荐方案

将任务视图的打开配置从：

```ts
prepareBeforeOpen: true
```

改为：

```ts
prepareBeforeOpen: false
```

任务视图配置同时适用于 `task` 和 `draft` 资源。普通主区域替换时，工作流变为：

```text
点击
  → 当前视图的 beforeClose 保护通过（如需确认，先完成确认）
  → WorkbenchController 提交目标视图
  → 目标视图显示现有 loading 状态
  → TaskWorkspacePool 完成初始化后显示目标会话/草稿
  → 最近时间线页沿用现有加载；更早历史沿用现有分页，在滚动到顶部时加载
  → 文件树和文件内容仍在文件面板/预览打开后按需加载
```

目标会话的最近消息不会在 `TaskWorkspacePool.open()` 完成前提前展示。本次不拆分初始化阶段。`beforeClose` 仍在提交目标视图之前执行，草稿保护和资源清理不变；如关闭保护需要用户确认，切换会等确认完成。

## 5. 用户体验

### 当前体验

```text
点击
  → 旧会话继续显示
  → 等待目标会话完整初始化
  → 突然切换
```

### 目标体验

```text
点击
  → 关闭保护通过后，目标视图立即高亮并提交
  → 初始化期间显示目标视图的 loading
  → 初始化完成后显示目标会话内容
  → 用户滚动到顶部时按现有分页加载更早历史
```

不显示旧会话的消息作为目标会话内容，避免会话归属混淆。正在运行的 Agent 输出继续使用已有事件流更新；历史消息不引入新的网络流式协议。

## 6. 异常行为

- 目标会话加载失败：显示目标视图的失败状态和重试按钮。
- 用户连续点击多个会话：沿用现有的同窗请求取消机制，最后一次点击生效。
- 打开新建草稿时，普通主区域的切换时机也会变为先切换后加载；未发送内容的确认和草稿保存流程不变。

## 8. 风险与取舍

**风险：** 目标会话读取失败时，用户看到的是目标会话的失败页，而不是继续停留在旧会话。

**取舍：** 这是即时切换方案的正常行为，用户能明确看到点击已经生效，并可直接重试；如果后续确认必须失败回退到旧会话，再单独设计回滚机制，不在本次范围内引入复杂事务逻辑。

## 10. 文件与术语说明

| 原名称 | 中文含义 | 用途 |
|---|---|---|
| `prepareBeforeOpen` | 打开前准备开关 | 控制视图是准备完成后再切换，还是先切换再加载 |
| `WorkbenchController` | 工作台控制器 | 管理视图打开、关闭和切换 |
| `DesktopTaskContribution.vue` | 桌面任务视图组件 | 显示任务加载中、失败或完整任务界面 |
| `TaskWorkspacePool` | 任务工作区池 | 创建和管理会话对应的任务工作区 |
| `ready` | 视图已准备完成 | 当前用于阻塞视图提交的完成信号 |

## 11. 审阅结论

- 接受加载失败时显示目标视图的失败状态和重试入口，不新增回退事务。
- 普通主区域任务视图替换统一先切换后加载；该时机也适用于新建草稿，关闭确认和保存流程保持不变。
- 分屏打开、工作区数据模型和文件按需加载行为不变。
- 不改现有时间线分页；本次聚焦于视图提交时机。
